Systems biology views biological processes as interconnected networks rather than isolated pathways. By integrating multi-omics data — transcriptomics, proteomics, metabolomics — with interaction networks, we can understand how molecular changes propagate through biological systems.

Protein-Protein Interaction (PPI) networks represent physical or functional associations between proteins. Nodes are proteins, edges represent interactions. Highly connected proteins (hubs) tend to be essential. PPI networks help identify functional modules, predict protein function, and prioritise drug targets.

Key Resources & Tools

STRING (string-db.org)

Largest PPI database. Integrates experimental data, co-expression, text mining, genomic context. Confidence scores 0–1. Use score > 0.7 for high-confidence interactions.

Cytoscape

Desktop software for network visualisation and analysis. Supports plugins (clusterMaker, MCODE for module detection, CytoHubba for hub identification). Essential for publication figures.

BioGRID

Curated repository of experimentally validated interactions (protein, genetic, chemical). Over 2 million interactions. Higher confidence than computationally predicted interactions.

Network Analysis Concepts

Degree

Number of connections a node has. High-degree nodes (hubs) are often essential genes. Degree distribution follows a power law in biological networks (scale-free property).

Betweenness Centrality

How often a node lies on shortest paths between other nodes. Bottleneck proteins control information flow through the network — they are often good drug targets.

Clustering Coefficient

How densely connected a node's neighbours are. Nodes in protein complexes have high clustering. Used to detect functional modules (MCODE algorithm).

Modules/Communities

Densely connected subnetworks often correspond to protein complexes or functional pathways. Detect with MCODE, Louvain, or Markov clustering (MCL).

# ─── Network analysis in Python with NetworkX ─── pip install networkx pandas matplotlib # Build network from STRING export import networkx as nx import pandas as pd edges = pd.read_csv("string_interactions.tsv", sep="\t") edges = edges[edges["combined_score"] > 700] # High confidence G = nx.from_pandas_edgelist(edges, "protein1", "protein2", edge_attr="combined_score") # Key network metrics print(f"Nodes: {G.number_of_nodes()}, Edges: {G.number_of_edges()}") print(f"Density: {nx.density(G):.4f}") print(f"Components: {nx.number_connected_components(G)}") # Find hub genes (top 10 by degree) degree = dict(G.degree()) hubs = sorted(degree, key=degree.get, reverse=True)[:10] print("Hub genes:", hubs) # Betweenness centrality (bottleneck nodes) betw = nx.betweenness_centrality(G) bottlenecks = sorted(betw, key=betw.get, reverse=True)[:10] # Community detection (Louvain) from networkx.algorithms.community import louvain_communities communities = louvain_communities(G, resolution=1.0) print(f"Found {len(communities)} communities")

This is why STRING scores matter more than STRING edges. STRING combines experiments, databases, co-expression, text mining and genomic context into one confidence score from 0 to 1. The measurements that describe a network

  • Degree: how many partners a node has. Interaction networks are scale-free in shape: most proteins have few partners and a handful have very many.
  • Betweenness centrality: how often a node lies on the shortest path between other nodes. High-betweenness bottlenecks often connect functional modules and are frequently essential.
  • Clustering coefficient: how far a node's partners also interact with each other. Dense neighbourhoods often correspond to physical complexes.
  • Modules: groups found by algorithms such as MCODE, Louvain or Leiden, usually interpreted as complexes or pathways.
Hubs are biased. Well-studied proteins such as TP53 or UBC have thousands of recorded partners largely because thousands of papers looked for them. Before claiming your hub is biologically central, ask whether it is simply famous. Comparing against a degree-matched random background helps.

A reproducible workflow

# Fetch a network for a gene list and find modules, in R library(STRINGdb) string_db <- STRINGdb$new(version = "12", species = 9606, score_threshold = 700) # high confidence only mapped <- string_db$map(gene_df, "gene_symbol", removeUnmappedRows = TRUE) net <- string_db$get_subnetwork(mapped$STRING_id) library(igraph) deg <- sort(degree(net), decreasing = TRUE) # hubs btw <- sort(betweenness(net), decreasing = TRUE) # bottlenecks mods <- cluster_leiden(net, objective_function = "modularity")

For interactive work, Cytoscape with the stringApp is the usual choice: it imports the network, lets you map expression values onto node colour, and runs MCODE for module detection. Export the session alongside your figure so the thresholds are recoverable.

Using a network honestly

A network figure is easy to produce and hard to interpret. Three habits make it worth including:

  1. Start from a defined gene list (for example, your differentially expressed genes) rather than from a protein of interest and its neighbours, which guarantees a pretty picture and no statistics.
  2. Test against a background. STRING reports a PPI enrichment p-value: does your list have more interactions among its members than a random list of the same size? If not, the network says nothing.
  3. Make the claim testable. "Protein X is a hub" is not a result. "Knocking down X should affect these five module members" is.

Gene Regulatory Networks (GRNs) describe how transcription factors (TFs) control the expression of target genes. Unlike PPI networks which show physical contacts, GRNs show regulatory relationships — which TFs activate or repress which genes. Multi-omics integration combines transcriptomics, proteomics, metabolomics, and epigenomics data to build comprehensive models of cellular regulation.

GRN Inference Methods

SCENIC / pySCENIC

Infers GRNs from single-cell RNA-seq data. Uses GRNBoost2 (random forest) for coexpression, then validates with TF binding motif enrichment (RcisTarget). Outputs regulon activity scores per cell.

Best for scRNA-seq
WGCNA

Weighted Gene Co-expression Network Analysis. Groups genes into co-expression modules, correlates modules with clinical traits. Excellent for bulk RNA-seq. Widely used, well-cited. R package.

ARACNe / VIPER

Mutual information-based network inference. VIPER then infers TF activity from target gene expression. Widely used in cancer biology for identifying master regulators.

CellOracle

Combines scRNA-seq + scATAC-seq to build context-specific GRNs. Simulates TF perturbations in silico. Predicts effects of gene knockouts on cell fate.

Multi-Omics Integration Strategies

Integrating multiple data types reveals biology invisible to any single assay:

Correlation-based

Correlate mRNA ↔ protein levels, mRNA ↔ metabolite levels. Discordant pairs (high mRNA, low protein) suggest post-transcriptional regulation. Tools: mixOmics (R), MOFA+.

Pathway-based

Map all omics data onto KEGG/Reactome pathways. Identify pathways with consistent changes across data types. Tools: Paintomics, iPath, OmicsNet.

Factor analysis (MOFA+)

Multi-Omics Factor Analysis decomposes multiple data matrices into shared latent factors. Identifies which sources of variation are shared vs unique to each data type.

Network-based

Construct multilayer networks connecting genes, proteins, metabolites. Network propagation algorithms (Random Walk with Restart) identify key regulators driving multi-level changes.

Co-expression networks: WGCNA in outline

A gene regulatory network built from expression data starts from a simple idea: genes that are regulated together vary together across samples. WGCNA formalises this:

  1. Correlate every gene with every other gene across the samples.
  2. Raise the correlations to a power β (soft thresholding), so that strong correlations dominate and weak ones fade. β is chosen so the resulting network is approximately scale-free.
  3. Cluster genes into modules of tightly co-expressed genes, each given a colour name.
  4. Summarise each module by its first principal component, the eigengene.
  5. Correlate eigengenes with traits (treatment, time, clinical measurement) to find the modules that matter.
# WGCNA on variance-stabilised counts (samples in rows, genes in columns) library(WGCNA) sft <- pickSoftThreshold(datExpr, powerVector = 1:20, networkType = "signed") # choose the lowest power where the scale-free fit R² exceeds ~0.85 net <- blockwiseModules(datExpr, power = sft$powerEstimate, networkType = "signed", minModuleSize = 30, mergeCutHeight = 0.25, numericLabels = TRUE) MEs <- moduleEigengenes(datExpr, net$colors)$eigengenes cor(MEs, traits, use = "p") # which module tracks which trait?
WGCNA needs samples, not just genes. Fifteen samples is the usual practical minimum and twenty or more is better; with six samples the correlations are noise. Correlation is also not direction: a co-expression module shows genes moving together, not that one regulates another. For direction you need perturbation data, time courses, or methods such as GENIE3 and SCENIC that use regulator-target structure.

Integrating different kinds of data

StrategyHow it worksUse when
Early integrationConcatenate all features into one matrix and analyse onceRarely best: the layer with most features dominates
Intermediate (joint) integrationLearn shared latent factors across layers (MOFA2, DIABLO, iCluster)The usual choice when the same samples have several data types
Late integrationAnalyse each layer separately, then combine the result listsWhen layers come from different samples or cohorts

MOFA2 is a good default for unsupervised work: it finds latent factors and reports how much variance each factor explains in each layer, which immediately shows whether a factor is shared across omics or private to one. DIABLO (in mixOmics) is the supervised counterpart when you have a known outcome to predict.

What usually goes wrong

  • Scale. Layers have different units, ranges and feature counts. Transform and scale each one before integration, or the largest layer decides the answer.
  • Batch effects. Each platform has its own batch structure. Correct within each layer first, and check that factors do not simply encode processing date.
  • Missing layers. Not every sample has every measurement. MOFA2 handles missing views; many other methods silently drop the sample.
  • Over-interpretation. Shared variation is correlation across layers, not a causal chain from methylation to transcript to protein. Transcript and protein levels correlate only moderately, typically around r = 0.4 to 0.6, for real biological reasons.
Design for integration from the start. The single thing that most improves a multi-omics study is collecting every layer from the same samples, split at the same time, with the conditions balanced across batches in every platform. No integration method recovers what a confounded design destroys.
