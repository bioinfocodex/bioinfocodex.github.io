Whole-genome and whole-exome sequencing reveal the genetic blueprint of an organism. This module covers variant calling, genome assembly, and annotation.

Variant calling is the process of identifying positions in a sequenced genome where the sample differs from the reference. These differences include SNPs (single nucleotide polymorphisms — one base changed to another), indels (insertions or deletions of one or more bases), and MNVs (multi-nucleotide variants — multiple adjacent substitutions). Variant calling is the foundation of clinical genomics, population genetics, and disease gene discovery.

Variant Types and Zygosity

SNP (Single Nucleotide Polymorphism)

A single base change: e.g., reference A → alternative G. The most common variant type. ~4–5 million SNPs per human genome.

Indel (Insertion / Deletion)

Insertion of extra bases or deletion of reference bases. Short indels (1–50bp) are called by GATK. Larger structural variants require specialised tools (Manta, DELLY).

Homozygous reference (0/0)

Both copies of the chromosome carry the reference allele. This position is not a variant in this individual.

Heterozygous (0/1)

One chromosome carries the reference allele, the other carries the alternative. Expect ~50% of reads supporting each allele.

Homozygous alternative (1/1)

Both chromosomes carry the alternative allele. Expect ~100% of reads supporting the ALT allele.

MNV (Multi-Nucleotide Variant)

Two or more adjacent bases changed simultaneously (e.g., AG → TC). Often caused by a single mutational event. Correctly phasing these is important for protein impact prediction.

Why We Mark Duplicates

During library preparation, PCR amplification creates identical copies of DNA fragments. These PCR duplicates are not independent observations — they all come from the same original molecule. If not removed, they artificially inflate the number of reads supporting a variant, leading to false-positive variant calls. Duplicate marking identifies reads with identical start and end coordinates and flags all but one as duplicates.

How HaplotypeCaller Works

GATK's HaplotypeCaller does not simply count bases at each position. Instead, it performs local de novo assembly in active regions (regions with evidence of variation). It: (1) identifies active regions where the data deviates from the reference, (2) assembles the reads in that region into candidate haplotypes, (3) realigns reads to these haplotypes using a pair-HMM, and (4) assigns genotype likelihoods. This approach is more accurate than simple pileup-based callers, especially for indels and complex variants.

Complete GATK4 Pipeline

# Step 1: Align with BWA-MEM2 (faster successor to BWA-MEM) bwa-mem2 mem -t 8 -R "@RG\tID:sample\tSM:sample\tPL:ILLUMINA\tLB:lib1" \ reference.fa sample_R1.fastq.gz sample_R2.fastq.gz \ | samtools sort -@ 8 -o sample.bam samtools index sample.bam # Step 2: Mark PCR duplicates gatk MarkDuplicates \ -I sample.bam \ -O sample_markdup.bam \ -M metrics.txt \ --CREATE_INDEX true # Step 3: Base Quality Score Recalibration (BQSR) # Corrects systematic errors in base quality scores gatk BaseRecalibrator \ -I sample_markdup.bam -R reference.fa \ --known-sites dbsnp.vcf.gz \ --known-sites mills_indels.vcf.gz \ -O recal.table gatk ApplyBQSR \ -I sample_markdup.bam -R reference.fa \ --bqsr-recal-file recal.table \ -O sample_recal.bam # Step 4: Call variants (per-sample GVCF mode) gatk HaplotypeCaller \ -I sample_recal.bam -R reference.fa \ -O sample.g.vcf.gz \ -ERC GVCF # Step 5: Joint genotyping (for cohorts) gatk GenotypeGVCFs -R reference.fa \ -V sample.g.vcf.gz \ -O sample.vcf.gz # Step 6: Filter variants gatk VariantFiltration -V sample.vcf.gz -O sample_filtered.vcf.gz \ --filter-expression "QD < 2.0" --filter-name "LowQD" \ --filter-expression "MQ < 40.0" --filter-name "LowMQ" \ --filter-expression "FS > 60.0" --filter-name "HighFS" \ --filter-expression "SOR > 3.0" --filter-name "HighSOR"

Hard Filtering vs VQSR

Hard filtering

Apply fixed thresholds on quality metrics (QD, MQ, FS, SOR). Simple and works for any project size. Use for small cohorts (<30 samples), non-model organisms, or targeted panels.

VQSR (Variant Quality Score Recalibration)

Machine learning approach that learns the quality profile from known true variants (e.g., HapMap, 1000 Genomes). More accurate but requires large cohorts (>30 whole genomes) and curated training resources.

Quality Filter Annotations Explained

QD (QualByDepth)

Variant quality normalised by depth. Low QD (<2) means the variant quality is low relative to coverage — likely a false positive.

MQ (MappingQuality)

RMS mapping quality of reads at the site. Low MQ (<40) indicates reads are mapping to multiple locations — the region is ambiguous.

FS (FisherStrand)

Strand bias estimated by Fisher's exact test. High FS (>60 for SNPs) means the variant is only supported by reads on one strand — likely an artefact.

SOR (StrandOddsRatio)

Alternative strand bias metric. More robust than FS for high-coverage data. SOR > 3 indicates significant strand bias.

Visualising Variants in IGV

Always visually inspect candidate variants in the Integrative Genomics Viewer (IGV). Load the BAM file and VCF together, navigate to a variant position, and check: (1) Is there sufficient read depth? (2) Are both strands represented? (3) Are the variant-supporting reads properly mapped (no soft-clipping artefacts)? (4) Is the region not in a repeat or low-complexity sequence?

BQSR requires known variant databases (dbSNP, Mills indels). For non-model organisms without these resources, skip BQSR and use more stringent hard filtering instead.

The key idea in HaplotypeCaller is local reassembly. Rather than reading each position column by column, it finds regions that look variable, assembles the reads there into candidate haplotypes, and realigns every read against them. This is why it handles indels so much better than older callers: an indel misaligned by a conventional aligner produces a cluster of false mismatches, and reassembly dissolves them.

The GVCF idea

Calling each sample straight to a VCF creates the "N+1 problem": adding one sample means recalling everything, because a site is only in the file if that sample varied there. A GVCF instead records every position, including a confidence that the sample matches the reference. Joint genotyping then combines GVCFs across the cohort. Adding sample 101 means producing one more GVCF and redoing only the joint step.

# Per sample: align, mark duplicates, call to a GVCF bwa mem -t 16 -R '@RG\tID:S1\tSM:S1\tPL:ILLUMINA\tLB:lib1' ref.fa S1_R1.fq.gz S1_R2.fq.gz \ | samtools sort -@ 4 -o S1.bam - gatk MarkDuplicates -I S1.bam -O S1.md.bam -M S1.metrics.txt samtools index S1.md.bam gatk HaplotypeCaller -R ref.fa -I S1.md.bam -O S1.g.vcf.gz -ERC GVCF # All samples together gatk GenomicsDBImport --genomicsdb-workspace-path db -L chr20 \ -V S1.g.vcf.gz -V S2.g.vcf.gz -V S3.g.vcf.gz gatk GenotypeGVCFs -R ref.fa -V gendb://db -O cohort.vcf.gz
The read group (-R) is not optional. GATK refuses to run without it, and for good reason: SM identifies the sample, LB identifies the library (so duplicates are marked within the right library), and ID identifies the run. Getting SM wrong merges two samples into one, silently.

Filtering when you cannot use VQSR

VQSR learns the difference between true and false variants from known sites, but it needs thousands of samples' worth of variants to train on. For a handful of exomes, or a non-model organism with no truth set, use hard filters instead. GATK's recommended starting points:

# SNPs gatk VariantFiltration -V snps.vcf.gz -O snps.filtered.vcf.gz \ --filter-name "QD2" --filter-expression "QD < 2.0" \ --filter-name "QUAL30" --filter-expression "QUAL < 30.0" \ --filter-name "FS60" --filter-expression "FS > 60.0" \ --filter-name "MQ40" --filter-expression "MQ < 40.0" \ --filter-name "MQRS-12.5" --filter-expression "MQRankSum < -12.5" \ --filter-name "RPRS-8" --filter-expression "ReadPosRankSum < -8.0" # Indels are noisier, so the thresholds differ: QD < 2, FS > 200, ReadPosRankSum < -20

Each annotation detects a specific artefact. FS and SOR measure strand bias: a real variant appears on both strands, a sequencing artefact often on one. MQ and MQRankSum catch variants supported only by poorly mapped reads, typical of repeats. ReadPosRankSum catches variants that only ever appear near the ends of reads, which is where errors concentrate.

Calling somatic variants with a germline caller is a common and serious mistake: the caller assumes diploid genotypes and will discard exactly the low-fraction variants a tumour study is looking for.

Checking a callset

  • Ti/Tv ratio: transitions over transversions. About 2.0 to 2.1 for whole genomes, 2.8 to 3.0 for exomes. A value near 0.5 means your calls are mostly noise.
  • Number of variants: roughly 4 to 5 million per human genome, 20,000 to 25,000 per exome. An order of magnitude off means a problem.
  • Concordance with a truth set (GIAB samples such as NA12878) if you are validating a pipeline, scored with hap.py or RTG vcfeval.
  • Mendelian errors in a trio: a useful, assumption-free check on accuracy.

The Variant Call Format (VCF) is the standard file format for storing genetic variants discovered by variant calling pipelines. Understanding the VCF format in detail is essential for filtering, annotating, and interpreting variant data. A VCF file consists of header lines (metadata) followed by data lines (one variant per line), and can contain genotype information for one or many samples.

VCF File Structure

A VCF file has two sections: the header (lines starting with ##) and the data lines (tab-separated variant records). The header defines the meaning of INFO and FORMAT fields used in the data lines.

## VCF header lines (metadata) ##fileformat=VCFv4.2 ##INFO=<ID=DP,Number=1,Type=Integer,Description="Total read depth"> ##INFO=<ID=AF,Number=A,Type=Float,Description="Allele frequency"> ##FORMAT=<ID=GT,Number=1,Type=String,Description="Genotype"> ##FORMAT=<ID=GQ,Number=1,Type=Integer,Description="Genotype quality"> ##FORMAT=<ID=DP,Number=1,Type=Integer,Description="Read depth"> ##FORMAT=<ID=AD,Number=R,Type=Integer,Description="Allelic depths (REF,ALT)"> #CHROM POS ID REF ALT QUAL FILTER INFO FORMAT Sample1 chr1 925952 rs12345 G A 5000.1 PASS DP=45;AF=0.50 GT:GQ:DP:AD 0/1:99:45:22,23

Anatomy of a VCF Data Line

Let us dissect the example line above field by field:

CHROM: chr1

Chromosome where the variant is located.

POS: 925952

1-based position on the reference. For indels, this is the position of the base before the event.

ID: rs12345

dbSNP identifier if known, otherwise "." (missing). Links to public variant databases.

REF: G / ALT: A

Reference allele and alternative allele. For SNPs: single bases. For a deletion: REF=ACG, ALT=A (CG deleted). For an insertion: REF=A, ALT=ATCG (TCG inserted).

QUAL: 5000.1

Phred-scaled quality score. QUAL 30 = 1/1000 chance the variant is wrong. QUAL 5000 = extremely confident. Higher is better.

FILTER: PASS

PASS means the variant passed all quality filters. Other values (e.g., "LowQD") indicate which filter(s) it failed.

Genotype Field (FORMAT + Sample)

The FORMAT column defines the order of fields in the sample column(s). In our example: GT:GQ:DP:AD → 0/1:99:45:22,23

GT: 0/1

Genotype. 0 = reference allele, 1 = first ALT allele. So 0/1 = heterozygous. 0/0 = homozygous reference. 1/1 = homozygous alternative. 0|1 = phased heterozygous.

GQ: 99

Genotype quality. Phred-scaled confidence that the genotype call is correct. GQ 99 = very high confidence. Low GQ (<20) means the genotype is uncertain.

DP: 45

Read depth at this position for this sample. For WGS, typically 30x. For WES, typically 50–100x. Low depth (<10) = unreliable genotype.

AD: 22,23

Allelic depths. 22 reads support REF (G), 23 reads support ALT (A). For a heterozygous call, expect roughly 50:50. Severe imbalance may indicate an artefact.

bcftools: Filtering, Extracting, and Merging VCFs

# Install bcftools conda install -c bioconda bcftools # View basic stats bcftools stats sample.vcf.gz | head -40 # Filter: keep only PASS variants with depth >= 20 bcftools view -f PASS -i 'DP>=20' sample.vcf.gz -Oz -o filtered.vcf.gz # Extract only SNPs (exclude indels) bcftools view -v snps sample.vcf.gz -Oz -o snps_only.vcf.gz # Extract only indels bcftools view -v indels sample.vcf.gz -Oz -o indels_only.vcf.gz # Extract specific regions bcftools view -r chr1:1000000-2000000 sample.vcf.gz # Extract specific samples from a multi-sample VCF bcftools view -s Sample1,Sample2 cohort.vcf.gz -Oz -o subset.vcf.gz # Merge multiple single-sample VCFs bcftools merge sample1.vcf.gz sample2.vcf.gz sample3.vcf.gz \ -Oz -o merged.vcf.gz # Index a VCF (required for most operations) bcftools index -t filtered.vcf.gz

Variant Annotation with SnpEff

SnpEff annotates each variant with its predicted functional impact on genes, transcripts, and proteins. It adds an ANN field to the INFO column.

# Install SnpEff conda install -c bioconda snpeff # List available databases snpEff databases | grep -i "homo_sapiens" # Download the human genome database snpEff download GRCh38.105 # Annotate variants snpEff ann GRCh38.105 filtered.vcf.gz > annotated.vcf # Generate an HTML summary report snpEff ann -stats snpEff_summary.html GRCh38.105 filtered.vcf.gz > annotated.vcf # Extract high-impact variants only cat annotated.vcf | snpSift filter "ANN[*].IMPACT = 'HIGH'" > high_impact.vcf

Variant Functional Categories

Synonymous (LOW impact)

DNA change that does NOT alter the amino acid (e.g., GCC→GCT both encode Alanine). Usually benign due to codon degeneracy.

Missense (MODERATE impact)

DNA change that alters one amino acid (e.g., GAG→GTG: Glutamate→Valine). May or may not affect protein function depending on the position and amino acid properties.

Nonsense / Stop-gained (HIGH impact)

Creates a premature stop codon (e.g., CAG→TAG: Glutamine→Stop). Truncates the protein. Often loss-of-function. Subject to nonsense-mediated decay (NMD).

Frameshift (HIGH impact)

Insertion or deletion not divisible by 3. Shifts the reading frame, altering all downstream amino acids and usually creating a premature stop. Almost always loss-of-function.

Splice site (HIGH impact)

Variant at an exon-intron boundary (donor GT or acceptor AG). Disrupts normal splicing, potentially causing exon skipping or intron retention. Often pathogenic.

In-frame indel (MODERATE impact)

Insertion or deletion divisible by 3. Adds or removes amino acids without shifting the reading frame. Effect depends on the protein domain affected.

Clinical Interpretation Resources

ClinVar

NCBI database of variants with clinical significance (pathogenic, likely pathogenic, benign, VUS). The primary resource for clinical variant interpretation. Query by rsID or genomic coordinates.

gnomAD

Population allele frequencies from >140,000 exomes and >76,000 genomes. A variant with AF > 1% in gnomAD is almost certainly benign. Essential for filtering common polymorphisms.

Filtering strategy for clinical variants: Start with ~4 million variants → filter PASS only → remove AF > 0.01 in gnomAD → keep HIGH/MODERATE impact → check ClinVar → manual review in IGV. This typically reduces to a manageable list of 50–200 candidate variants.

The header is part of the data

Every VCF begins with header lines that define what the abbreviations in the file mean. They are not decoration: a tool that reads the file uses them to know the type and arity of each field, and a VCF whose header does not match its body will be rejected or silently misread.

##fileformat=VCFv4.3 ##reference=file:///ref/GRCh38.fa ##contig=<ID=chr7,length=159345973> ##INFO=<ID=DP,Number=1,Type=Integer,Description="Total read depth"> ##INFO=<ID=AF,Number=A,Type=Float,Description="Allele frequency"> ##FORMAT=<ID=GT,Number=1,Type=String,Description="Genotype"> ##FORMAT=<ID=AD,Number=R,Type=Integer,Description="Allelic depths"> ##FILTER=<ID=LowQual,Description="Low quality"> #CHROM POS ID REF ALT QUAL FILTER INFO FORMAT SAMPLE1

Indels, multi-allelic sites, and why normalisation matters

# SNV: one base replaced chr7 140753336 . A T # Deletion: REF carries the anchor base plus what is removed chr1 100 . GTTA G # three bases deleted after position 100 # Insertion: the reverse chr1 100 . G GTTA # three bases inserted after position 100 # Multi-allelic: two alternates at one site chr2 500 . C T,G # genotype 1/2 means one T and one G, no reference allele

Indels have an anchor base because the format cannot represent an empty allele. They also have a left-alignment problem: in a repeat, the same deletion can be written at several positions, so two files can disagree about an identical variant. Normalising with bcftools norm -f ref.fa -m -any left-aligns indels and splits multi-allelic sites, and should be done before comparing or annotating any callset.

Annotation: from coordinates to consequences

A variant's position means nothing on its own. Annotation tools add what gene it hits, what it does to the protein, how common it is in the population, and what is known about it.

SourceAdds
VEP or SnpEffGene, transcript, consequence (missense, frameshift, splice site), protein change

ClinVarClinical interpretations submitted by laboratories, with review status
CADD, REVEL, SpliceAI, AlphaMissensePredicted deleteriousness; SpliceAI in particular catches splice effects far from the exon boundary

A variant has one consequence per transcript, and genes have many transcripts, so one variant can be "missense" and "intronic" and "upstream" at once. Decide in advance whether you report the canonical transcript, the MANE Select transcript, or the worst consequence, and apply it consistently.

Narrowing a rare-disease search

  1. Keep PASS variants with adequate depth and genotype quality.
  2. Remove anything common in gnomAD: a frequency above 0.1% rules out most severe recessive disease, and above 0.01% most dominant.
  3. Keep variants predicted to affect protein or splicing.
  4. Apply the inheritance model: de novo in a trio, compound heterozygous, homozygous recessive, X-linked.
  5. Intersect with a gene list for the phenotype, while keeping the unfiltered list for a second look.
Clinical interpretation follows published rules. The ACMG/AMP guidelines define evidence codes (PVS1 for a null variant in a gene where loss of function causes disease, PM2 for absence from population databases, and so on) that combine into five classes from benign to pathogenic. Prediction scores contribute one line of supporting evidence; they never establish pathogenicity on their own.

Next-generation sequencers read DNA in short stretches of 50–300 bp. Human genomic DNA is ~3 billion bp long — a molecule millions of times too large to sequence directly. Before any library can be prepared, the DNA must be broken into sequenceable fragments. The fragmentation method you choose affects coverage uniformity, sequence bias, DNA input requirements, and the cost of your experiment.

~3 billion bp

Human genome size — the full length of DNA that must be broken down before sequencing.

150–300 bp

Target fragment size for standard Illumina short-read sequencing. Longer fragments reduce cluster density.

30× depth

Minimum sequencing depth for confident variant calling in whole-genome sequencing.

4 methods

Probe sonication, acoustic shearing (Covaris AFA), enzymatic digestion, and tagmentation (Tn5).

The four fragmentation approaches

1 — Probe Sonication

A metal probe is submerged directly in the DNA sample and vibrates at ultrasonic frequency (~20 kHz). The vibration creates cavitation — microscopic bubbles that collapse violently, generating shear forces that break phosphodiester bonds. Fragment size is controlled by adjusting pulse duration, amplitude, and number of cycles.

Fragment size: 100 bp – 1 kb  ·  Bias: moderate  ·  Cost: medium (~$3k)
Common instruments: Branson SFX, Cole-Parmer. Protocols are flexible and easy to troubleshoot — ideal for teaching labs and pilot experiments.
2 — Covaris AFA (Acoustic Focused Acoustics)

Covaris instruments use a precisely focused acoustic transducer to deliver energy through the tube wall — the probe never touches the sample. This eliminates cross-contamination and heat, and produces extremely reproducible fragment size distributions. The gold standard for clinical genomics and large-scale sequencing projects.

Fragment size: 150–500 bp  ·  Bias: minimal  ·  Cost: high (~$80k+)
High capital cost but unmatched reproducibility. Required for regulatory-compliance environments (clinical labs, FDA submissions).
3 — Enzymatic Fragmentation

Nucleases (typically DNase I or a proprietary enzyme cocktail) are used to randomly cleave dsDNA. Reaction conditions (enzyme concentration, temperature, time) control fragment size. Requires only a thermocycler — no specialised equipment. Commercial kits include NEBNext Ultra II FS and Kapa HyperPlus.

Fragment size: 200–700 bp  ·  Bias: AT/GC bias possible  ·  Cost: low
Best for budget labs or high-throughput (96+ samples/day). Can be automated on liquid handling platforms (Hamilton, Tecan) for plate-scale processing.
4 — Tagmentation (Tn5 Transposase)

The Tn5 transposase enzyme simultaneously fragments DNA and inserts sequencing adapters in a single reaction — dramatically simplifying library preparation. Tn5 preferentially inserts at AT-rich, accessible regions of chromatin. This is both a bias (for WGS) and a feature (for ATAC-seq, where open chromatin is precisely what you want to measure).

Fragment size: 150–500 bp  ·  Bias: AT-rich preference  ·  Speed: very fast (1 step)
Essential for ATAC-seq — the assay is fundamentally built on Tn5 inserting at open chromatin. Also ideal for low DNA input (<10 ng) samples such as rare cell populations.

Where fragmentation sits in the full library preparation workflow

① Fragmentation ← You are here

DNA broken to 150–500 bp target size by sonication, enzymes, or Tn5 transposase.

② End repair

Ragged 3′/5′ ends polished to blunt ends using polymerase and exonuclease activity.

③ A-tailing

Single adenine added to the 3′ end for adapter ligation compatibility.

④ Adapter ligation

Platform-specific adapters and index barcodes ligated to both ends of each fragment.

⑤ Size selection

SPRI beads or gel electrophoresis remove very small and very large fragments.

⑥ PCR amplification

Library amplified (optional) to sufficient quantity for sequencing. Excessive cycles increase duplicates.

Key terms

Phosphodiester bond

The covalent bond linking nucleotides in a DNA strand. All fragmentation methods ultimately break this bond.

Cavitation

Formation and violent collapse of microscopic bubbles in liquid, driven by ultrasonic energy. The mechanical force shatters DNA.

AFA (Adaptive Focused Acoustics)

Covaris technology using a focused acoustic transducer to shear DNA without any probe touching the sample — eliminating cross-contamination.

DNase I

An endonuclease that cleaves both strands of dsDNA, commonly used in enzymatic fragmentation kits.

Tn5 transposase

A bacterial enzyme that inserts into dsDNA and simultaneously cuts and ligates adapters — the basis of tagmentation.

SPRI beads

Solid-Phase Reversible Immobilisation — magnetic beads used to selectively bind DNA fragments by size during cleanup steps.

Sequence bias

Tendency of a fragmentation method to over- or under-represent certain nucleotide sequences, affecting coverage uniformity.

ATAC-seq

Assay for Transposase-Accessible Chromatin — uses Tn5 tagmentation to map open chromatin regions genome-wide.

Tagmentation is fast, cheap and works from tiny inputs, which is why it dominates single-cell and ATAC-seq. Its insertion bias is acceptable when you are counting regions, and problematic when you need even coverage for variant calling in difficult regions. Sonication remains the choice when uniform coverage matters most.

Insert size is a design decision

The insert is the DNA between the adapters. Its size relative to the read length decides what you get:

  • Insert shorter than 2 × read length: the pairs overlap, and the sequencer reads into the adapter. Useful for merging pairs into longer, more accurate reads (amplicons); wasteful otherwise.
  • Insert around 300 to 500 bp with 2 × 150 reads: the usual choice. Pairs do not overlap, and the gap between them helps span repeats.
  • Insert much longer: better for spanning repeats and detecting structural variants, but harder to cluster efficiently.

The observed insert-size distribution, reported by Picard's CollectInsertSizeMetrics, is a quality check in itself: a sharp peak is a well-made library, and a long tail or a second peak indicates chimeric molecules or contamination.

PCR, and why people try to avoid it

Amplification introduces three problems: duplicates, which inflate apparent depth; GC bias, because extreme GC fragments amplify poorly and coverage drops over them; and errors introduced early that are then copied into many reads. PCR-free libraries avoid all three but need much more input DNA (typically 500 ng to 1 µg), which is why they are standard for high-quality whole-genome sequencing and impossible for single cells.

# Library quality metrics worth collecting on every run gatk CollectInsertSizeMetrics -I sample.bam -O insert.txt -H insert.pdf gatk CollectGcBiasMetrics -I sample.bam -R ref.fa -O gc.txt -CHART gc.pdf -S summary.txt gatk EstimateLibraryComplexity -I sample.bam -O complexity.txt # Duplicate rate, from the MarkDuplicates metrics file grep -A2 "LIBRARY" sample.metrics.txt | cut -f9

UMIs: counting molecules instead of reads

A unique molecular identifier is a short random barcode attached to each original fragment before amplification. Reads sharing a UMI and a position came from one molecule, so they can be collapsed into a single consensus observation. This turns duplicate removal from a heuristic (same start position) into a measurement, and it is essential wherever a rare variant must be distinguished from a PCR error: liquid biopsy, deep somatic sequencing, and single-cell counting.
